# SCUTOONS – project entry point

**Mandatory for every session except hotfixes: work on a GitHub issue** (mandymozart/scutoons, the board "SCUTOONS").
Start from the issue the owner names or create it before the first edit, name it in the commits (`Refs #N` /
`Fixes #N`), comment the result on it at the end. Open work never lives in docs or memory. How: RULES.md "Backlog".

Read **`agents/RULES.md`** (how agents work – read it whole) and **`agents/HANDOVER.md`** (the current state) first.
Then only the doc for what you touch:
- Open work: GitHub issues (`npm run backlog`, `gh issue list`). Owner decisions, one line each:
  `agents/DECISIONS.md` (grep it). Tool traps: `agents/GOTCHAS.md`. Night shifts / orchestrating other sessions:
  `C:\Development\ORCHESTRATION.md` + `agents/ORCHESTRATION.md`.
- How things are: DESIGN.md (UI) · DOCKING.md (panels, sidebar, dividers) · DATA.md · ITEMS.md · CATALOG.md ·
  ASSETS.md · MAP.md · EXPRESSIONS.md · PLATFORM.md · MCP.md · EMBASSY.md · NEWSLETTER.md (all in agents/).
- `agents/research/`: concepts, research, parked plans (line 1 = status). `agents/archive/`: frozen history – grep only.

Keep context small: targeted reads / greps over whole files. The docs stay tight – RULES.md "Docs".
