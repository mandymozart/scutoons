## A · The one core (deck, live, engine) — the dogma agents keep working around
- **A1** Deck logic is Rust in the ONE universal core (deck-core + its crates, native + wasm). A platform is only the compile target
  + thin adapters that move bytes / events between the core and a platform service. A decision (what plays, when, how a message
  is read) in TS or in a platform crate is a defect. (2026-11-02 [one-core]: "deck-core is everything … really need to stick to one universal core.")
- **A2** The browser is UI: no business logic. Editor Svelte / TS may hold authoring logic that exists before compile (state, drafts,
  selection, hints); rendering, sound, playback and every runtime rule are the core's; validity = core or server, an editor check is a hint.
  (2026-11-02 [browser-is-ui]: "browser, UI, no business logic.")
- **A3** Modules, rigs, scenes: Rust and universal, one implementation (play, flatten, checks) on every deck; no JS / TS modules, no second
  validator or interpreter per platform. The TS module host is deleted, not ported. (2026-11-02 [rigs-in-core], 2026-11-03 [ts-module-host])
- **A4** One engine, one clock, one governor: audio graph, tempo clock, quality governor, scene playback, wire codecs exist once in the
  core; native ≡ wasm is the contract (golden-render conformance). Scenes are API content, never TOML / TS constants. (2026-11-02 [one-engine] [tempo-core] [scenes-from-api])
- **A5** Devices (MIDI, camera, position, motion, video decode) are adapters feeding the core; a module never calls a browser API; video
  plays on the core's own playback. What a browser lacks (Web MIDI in Safari …) is ignored — that device gets a native build, no TS fallback. (2026-11-02 [devices-via-core] [own-video])
- **A6** No second copy: scenes, rules, defaults, ranges, status texts and monitoring numbers live once, in the core or one data file. A TS twin
  of Rust logic is a defect, even "trimmed", "for now" or "kept in TS because". Every control and readout has ONE owner of its state and number: the core (#362).
  The server too: a deck rule lives inside the deck, not in PHP; the server keeps only configuration stored in the database, unless a major shared schema or library carries
  the rule to both. A rule that crosses Rust / PHP / TS takes one of the four [contract] mechanisms (#474): generated types · generated
  tables and defaults · the server resolves, the client reads · shared test vectors; a deck rule's validity is decided once, on save, by
  the core through the build service's `/validate` (`CoreValidator`, #313) – no new bridge, no PHP copy. (2026-11-03 [no-duplicate]: "no duplicate code base in the end."; 2026-11-12 [deck-rules-in-deck]; 2026-11-10 [contract])
- **A7** Enforced, not trusted (2026-11-03 [core-only]: "enforce it even for dumb agents"; #363): `check:core-only` (every file that touches the engine; a new bridge
  file needs an `adapter:` / `ui:` line in scripts/bridge-files.json), `check:deck-deps` (no platform library in a core crate; main.rs only shrinks), the headless
  deck host (deck/headless: a move ticket is done when its `expected_fail` scenario is green). Baselines, budgets, allow rules and escapes only shrink – growth
  needs `Owner-approved-baseline:` in a commit message. Every deck brief carries the acceptance line; every merge runs the diff check; the audit reruns (AUDIT.md).
- **A8** Rust first for everything native (relay, bridge, audio, video, 3D, decks) — no Node / Electron — and as much as possible in the engine,
  also for the browser. (2026-10-29 [rust-first], 2026-10-31 [rust-engine])
- **A9** No backwards compatibility for the audio engine (nothing released; no A/B flags, no dual hosts). A deck takes a new module only by restart. (2026-11-02 [no-backcompat-engine], 2026-11-03 [module-restart])
- **A10** Performance and stability first: adapt to link and device (latest value wins, never a backlog), size by benches; every input and mapping is audiovisual. (2026-10-31 [perf-first] [audiovisual])
- **A11** Words: the native app is the **deck** (the stage is a part of it; the per-venue layer is the **stage environment**); "main" / "original" /
  "leader–follower", never master / slave; a bus that sums children is a folder bus. (2026-11-02 [names])
- **A12** Readers save nothing; the sound designer lives in the creator (creators / admins), the deck page holds only performance + hardware settings. (2026-11-02 [readers-save-nothing] [designer-in-creator])
- **A13** `npm run deck:ci` runs locally before every merge / push of deck work (GitHub's deck CI is by hand; a step green on the same clean tree is skipped by its stamp,
  `--fresh` forces; the full tier `deck:ci -- --full` builds release at the end of every shift and before a deck release); phones test over the LAN (`npm run dev:lan`). (2026-10-31, 2026-11-13 [deck-ci-local])
- **A14** Naming addresses: the part before `:` says where it comes from (`sound:`, `clock:`, `being:`, a track); places (`deck:`, `scene:`, `character:`, `item:`) and sources never share a word; the part after says what it is, a whole lowercase word, the same everywhere; the address is the identity, what a person reads is a label; every reserved word is listed once in the one parser (rig/address.rs) with a reason. (2026-11-09 [names])

## C · Backlog — GitHub issues (every session except hotfixes; 2026-10-19 [issues-only])
- **C1** All open work is an issue in `mandymozart/scutoons`; bugs, features, owner steps, open decisions. Never a backlog in docs, memory or HANDOVER. Old numbers 10.N: `gh issue list -s all --search '"10.N" in:body'`.
- **C2** Board **SCUTOONS**, six statuses (2026-10-20 [board]): Backlog (order top down = the owner's priority) · Proposals (new issues, open `decide`) · In progress · Review on staging (built + committed) · Deployed (closed by the push) · Done (the owner).
  Move your issue on start and finish — `npm run backlog -- set N "In progress"` — and put the step in every brief (2026-10-21 [board-move]: "important move issues alog the board once finihsed").
- **C3** Start: the owner names `#N`, or the request becomes an issue before the first edit (search first, then `gh issue create`); read `gh issue view N --comments`. Unattended: `npm run backlog`, top down.
- **C4** Anything outside the issue becomes a new issue (no status = the owner's inbox), unless the owner says so (CLAUDE.md one level up: ask before scope creep).
- **C5** Commits end `Refs #N`, the finishing one `Fixes #N` (never `#N` at a line start). End of session: one issue comment (built, open, checks), Finished → "Review on staging"; an open rest → the body's **Open:** list, status back to Backlog.
- **C6** Priorities are the owner's: agents move only their own issue (In progress, Review on staging, back); Backlog / reorder / Deployed / Done only on the owner's word. `decide` = assigned to the owner with options + your recommendation; `owner` = the owner's step (secrets, publishing, art).
- **C7** Issue form: title = the thing; one type label (`bug` `feature` `chore`), one `area:*`, one `complexity:S/M/L`, + `owner` / `decide`; body ≤ ~15 lines (owner quote · what / why · **Open:** · **Docs:**); a milestone only for a dated target. **Hotfix** (production broken, small): `hotfix:` commit, no issue.

## H · UI (canonical text: DESIGN.md — read the part you build; the creator's host: research/redesign/panels.html)
- **H1** Less UI is better UI; no duplicate controls (the text-language switch in the creator's Settings is the only one). [rules-only]
- **H2** Sizes in rem, never px — also sizes set from JS (÷ root font size); px only in tokens (border widths) and breakpoints. (2026-10-04 [rem]: "a dogma across the app")
- **H3** One `--control-height`; one tooltip style via `title`; bold very rarely; fieldsets without frames. (2026-10-02 [control-height] [bold])
- **H4** Standalone icon-only button = round – the kit's IconButton, also where the deck still draws a corner; a single icon without words may stand alone, without a pill, where room is tight; a group of icons and every toolbar stay bordered in their pill; grouped controls, tabs and anything with text follow the kit's pills (H12); tabs and panel titles carry no border at rest: the active one is brighter (the text colour, clear for the eye), the others muted, and a rounded border shows only on hover and while it is dragged – no outline whose radius fights the pill around it (2026-11-24); fold buttons quiet (`sc-quiet`). A select that filters or sorts in a toolbar is quiet in the same way as a tab – no box at rest, a rounded border on hover and while open; a select that sets a value in a form stays the boxed field (2026-11-24). (2026-10-07 [round-square], 2026-10-20 [fold], 2026-11-24 [editor-style])
- **H5** Spacing on a 1rem line; dividers run edge to edge. The creator's one layout model is the workspace host: every section a panel tab (`useTabs`, lib/shell/panels.ts), a workspace a preset of panels and tabs, the stage the whole window, no docks; admin / embassy keep AppShell (archive/DOCKING.md) until moved; pickers are modal drawers (`Sheet`). (2026-11-21 [editor-style])
- **H6** Confirmations in-page (`confirmDialog` / `askDialog`), never `confirm()`; primary action last, one only. Media fields are slots (preview = button, empty = dashed slot; multi-resolution = one slot with chips). (2026-10-03 [confirm])
- **H7** Empty list shows nothing; a muted `.sc-empty` line only when the area would be blank and it says what to do. Warnings can be accepted (✓, stored in the doc); errors can't. (2026-10-06 [empty-states])
- **H8** Shared 2D UI in Rust – the native editor, the deck's own UI, module interfaces – comes from ONE internal library, deck-kit (`deck/kit`), built on egui's primitives (text, layout, input, painting; not its widgets or look) and shared by the crates. Two component modules over one shared base: **editor** and **live** (audience-facing, its own style); behaviour and basic implementations are shared, the styling splits (tokens per style, `tokens.toml` live), and each module holds its own specialised components (most editor components are not needed live). No second component set, no layout format of our own, no PNG design loop. The web apps keep Svelte + `shared/ui`. (2026-11-11 [ui-kit])
- **H9** The web tools take the deck's look (deck-kit's editor tokens) with the OSCT editor's components and patterns (one kit in `shared/ui`) and its floating panels and workspaces (a panel defined once, any view shows it; opened items as tabs Scene · Asset · Show – replaced DOCKING.md, #751), and every step rethinks the UX it touches instead of porting layouts 1:1; not the "Brutalist tools" look; the creator, storyboard included, is desktop-only – no phone or responsive editing code, minimum 744 CSS px wide (the smallest tablet; below it only a notice); the embassy keeps its phone layout; the admin stays as it is until moved. Until #626's tokens land, H2–H7 hold as written. (2026-11-19 [editor-style], #626)
- **H10** No thick side bars marking a state or a box (a coloured `border-left` / inset shadow on a field, error, warning, selected row, quote or card) – anywhere, every app. A state shows as the outline, the text colour, an icon or a chip; a hairline divider between panes stays. (2026-11-21 [editor-style])
- **H11** Colours come only from the deck editor's scheme – deck-kit's editor tokens (`shared/tokens/editor.css`, generated from `kit/tokens.toml`, the kit's one source) through the tools' semantic tokens; the deck editor is the reference whenever a web tool looks different. Two grounds only: the stage (black at night; white by day in the creator) and the deck's floating panel (its see-through panel ground with the halo on text and icons); controls on the control colour. No grey sheets, boxes or page backgrounds behind content on the stage, no literal colours in tool CSS – the style check fails on both. **No ground is grey (owner 2026-11-24):** every ground – a control's, a panel's, a menu's, a popover's, a dialog's, a box's, a card's – is see-through, the stage showing through; an opaque grey fill does not exist. Where a draft or a capture shows a grey ground, this rule wins. **No signal hue (palette D, 2026-11-24):** on, focus, active and selected are the text colour (white by night, ink by day) – no blue accent, no lime, no green switch; the one primary action is the pressed fill; colour only says ok, warning and error. **The hue is taken out of the UI's own parts, not out of what it shows.** What keeps its colours: thumbnails and pictures (their own), the mixer (its strips' stripes and its meters), a group of spores (one of its six colours), outlet types (where a thing plays: the reader's page, a stage, an XR target, a light – their table sits beside the signals'), and signals – ports, pins and cables keep their signal's colour and shape from the deck's one signal table (`deck/kit/src/base/signal.rs`: event, control, clock, audio, picture, address, vote, scene, far – night and day); a kind OSCT has and the table lacks is adopted into it. (2026-11-24 [editor-style])
- **H12** One UI kit with recurring components, and the deck editor is its source of truth: every button, icon button, pill, pill tabs, menu, toggle, field, panel head and list row of the web tools is a `shared/ui` component that mirrors deck-kit's (`deck/kit/src/editor/controls.rs` and siblings) – its sizes, radii, insets and alignment, including deck-kit's concentric rule (a pill inside a pill is rounded by the outer radius less the inset, so the corners share a centre). No page or app draws its own copy; a shape the deck doesn't have is asked first. The style check fails on local button/pill/tab styling outside the kit. (2026-11-24 [editor-style])
- **H13** Design pictures (drafts in `research/redesign/` and every mock-up shown to the owner) are drawn with the kit's own tokens and components – `shared/tokens` and the `shared/ui` editor kit (H11, H12): round pills, the kit's badges, the stage and panel grounds – never an older style; a draft that needs a shape the kit lacks marks it as new. Badges (the kit's Chip) are small and delicate: round, the accent as line and words on a faint accent ground, never a solid blue fill. (2026-11-24 [editor-style])
- **H14** No info in the UI unless the member asks for it: no hint lines, legends, explanations or info buttons in panels – the UI is meant to be intuitive, and pros don't need it. What a control or a type means is its hover text (`title`), and the Info view (the creator's `info` view, deck-kit `info.rs`, from the OSCT editor; in no preset, opened through Views) shows the name and description of what is under the pointer – the member's choice. Panels show values, states and errors; rarely used filters shrink to icons whose hover says the rest. (2026-11-24 [editor-style])
- **H15** Depth layers. The tools have four depths, each with one ground: **the stage** (the content; black by night, white by day) · **surfaces** (the bar, the floating panels, the status line: the see-through panel ground, sharp) · **popovers** (menus, pickers, hover text: see-through like every ground (H11), at the stronger `popover_opacity` with the ink ring, so they read over a panel; sharp) · **the overlay** (the switcher, and a panel taken full – a box, never the whole window). Under the overlay everything is blurred, the bar included, so the place stays readable as context and nothing of it competes. Blur exists on the overlay level only: no panel, menu or popover blurs what lies behind it. Blur is an effect like the UI's animations: the "reduce motion" setting turns it off too (the overlay then lies on a plain ground). The workspace switcher is called "the switcher". (2026-11-24 [editor-style])
- **H16** The bar's middle holds the workspace row and nothing else. What a workspace has of its own – the Show's Cues, Problems, Who, Session, Vote and Demos – is a view of that workspace: listed in the ☰ Views with the four states (hidden · panel · stage · full), never a pill of its own in the bar. (2026-11-24 [editor-style])
- **H17** The tools do not flag what is missing. A blank slot, a missing version or a missing credit may be on purpose: no "wanted" or "missing" groups, counts or warnings in panels (the Library's Blank – wanted · Missing versions · Missing credits go). A member who wants to see the gaps asks for them. (2026-11-24 [editor-style])
- **H18** Sending out has one pattern. Publish (drafts to readers) and Flash (a show to the decks) are the same act: one icon in the bar, with a dot when something is not out yet; one dialog on the overlay level that lists what goes out, ticked, with All and None; one primary button with the count; the confirm where one is needed; a report in the same place. No second way in from a panel – except the switcher's Needs review box, which has a Publish button to the same dialog (owner 2026-11-24: "there's just no publish button there. Just needs a button"). (2026-11-24 [editor-style])
- **H19** No refresh buttons. When a newer version of what is open exists, the tool says so and offers Reload – the same notice in both apps, shown as soon as the tool knows, not only when a save is refused. The deck's Load button goes. (2026-11-24 [editor-style])
