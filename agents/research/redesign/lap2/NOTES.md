## Decided in the planning session (2026-11-24)
- **B1 – Views live only in the ☰ menu** (owner: *"Only the ☰"*), not on the workspace tab's menu. Still open: whether the workspace tab keeps its own menu for Save / Rename / Back to the last save (B2).
- **A3 – no Views on the switcher's cards** (owner: *"the views there – that is stupid. Redraw"*).
- **One switcher for both apps** (owner: *"workspaces from the deck or the creator should be shown vice versa … those workspace links will open the respective deck if active, jump into the workspace and the last content it had"*) – how: DECK-LINK.md.
- **Short placeholders** (owner: *"too long placeholder text – make it simple"*): a search field says "Find", no list of what it finds.
- **Decided: the creator becomes an Electron app in this lap** (owner: *"perhaps we can also plan to put the creator into an Electron app, since we are slowly tying it more into a desktop editing experience"* · *"Electron for this lap"*). Electron ships its own Chromium (as the deck OS does). For the plan: Windows, macOS and Arch; its own `scutoons-creator://` and one instance; the deck link through the two apps on the machine (DECK-LINK.md); files and local folders; signing and updates beside today's static deploy (**the web creator stays for now** – owner 2026-11-24: *"Keep the web version"* · *"for now. But I am not sure if the creator needs to stay online. It should be very much the same code, since the local Electron version is just a wrapper"* – one codebase: the Electron app wraps the same creator build; the desktop parts sit in the wrapper and are optional in the code, so the web version keeps working and can be dropped later without a rewrite). No earlier decision against it (2026-10-16 "PWA, not native yet" is the reader's).
- **The user menu opens under the account icon; the swipe up was meant for the switcher – and is dropped** (owner, on A5: *"explain why this should go down there?"* · *"I wanted the app switcher dashboard to be swiped up. But also this behaviour interferes with system defaults so it's very unlikely feasible"*). Point 56 was read wrong last night (the user menu instead of the switcher). The swipe up from the bottom edge collides with the systems' own gestures (iPad home, Windows / Android taskbar), so no swipe: the switcher opens with Alt Tab / Ctrl K / ⌘K, the user menu drops down under the account icon like the ☰ menu.
- **Design dogma – tabs and panel titles** (owner, on the Log panel's title): no border at rest; the active one brighter, the others muted; a rounded border only on hover and while dragged. RULES H4, law.md 2026-11-24. Every lap 2 screen draws tabs so; the kit's PillTab and panel tabs change in lap 2 (creator and deck).
- **Design dogma – workspace cards** (owner, on B7: *"not schematic – an actual screen capture. Also use the entire card and have the text overlay over that image"*): a card's picture is a real capture of the workspace as last left (#842), filling the whole card; the name and the last content lie over the picture (the kit's halo for legibility), the ✕ too. Applies to both switchers (A3, A3b, B7, D1) and to #842's build.
- **Thought aloud – a character is 2D-first or 3D-first** (owner, on C4: *"here we need a concept of how to show the 3D on the stage more prominently. Perhaps characters can have a preference note, if they are primarily 3D or 2D. Most start 2D with a sketch and at some point are ready for 3D. Depends on the creators in the end what to go for – a 2D world or a 3D world."*). Open: whether the preference sits on the character or on the toon / world.
